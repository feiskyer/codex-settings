# 规格文档审阅提示词模板

需要让独立 Subagent 审阅规格文档时，使用下面的提示词。

**目标：** 判断规格是否完整、一致、表达清楚，并且已经具备进入实施计划阶段的条件。

**使用时机：** 复杂规格需要独立审阅且委派已获授权时。使用实际文件路径，不限定存放目录；把原始需求和已确认的约束一并交给审阅者。

```text
Subagent（通用型）：
  description: "审阅规格文档"
  prompt: |
    你是一名规格文档审阅者。请判断这份规格是否完整，并确认它能否直接用于制定实施计划。

    **待审阅文件：** [SPEC_FILE_PATH]
    **原始需求与已确认约束：** [REQUEST_AND_CONSTRAINTS]

    只审阅，不修改文件或开始实现。先对照需求判断覆盖是否完整，不把主控的结论当作证据。

    ## 检查内容

    | 类别 | 重点检查 |
    | --- | --- |
    | 完整性 | 是否存在 TODO、占位符、TBD 或未完成章节 |
    | 一致性 | 文档内部是否自相矛盾，不同章节的要求是否冲突 |
    | 清晰度 | 是否存在可能让实现者做出两种不同理解的模糊要求 |
    | 范围 | 是否覆盖已请求的交付；多个子系统的边界、依赖和阶段是否清楚 |
    | YAGNI | 是否加入了用户没有要求的功能，或者存在明显过度设计 |

    ## 判断尺度

    只指出会真正影响实施计划的问题。

    缺失关键内容、要求互相冲突，或者一句需求可以被理解成两种不同实现，这些需要指出。措辞润色、个人风格偏好、某一章节比其他章节短，不属于阻塞问题。

    报告有证据的实施阻塞；没有此类问题时通过，不为填满表格制造建议。

    ## 输出格式

    # 规格审阅结果

    **状态：** 通过｜发现问题

    **需要修复的问题：**
    - [章节名称]：[具体问题] —— [为什么会影响实施计划]

    **改进建议（仅供参考，不影响通过）：**
    - [可选的改进建议]
```

审阅结果包含状态，以及有依据的问题和建议（如有）。不要强制填写没有内容的章节。
